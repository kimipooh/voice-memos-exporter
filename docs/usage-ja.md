# CLIの使い方

[English: usage.md](usage.md)

`export_voice_memos.py` の詳細リファレンスです。最短の使い方はルートの [README-ja.md](../README-ja.md) を参照してください。

## モード

`--list`、`--all`、`--search` のうち少なくとも1つが必要です。

- `--list` は書き出さずに録音を一覧表示します。`--list --search TEXT` は一致した録音だけを表示します。
- `--list` がなければ、`--all` または `--search` が書き出しを実行し、`--output` が必要になります。

## オプション

| オプション | 意味 |
|---|---|
| `-h`, `--help` | helpを表示して終了します。 |
| `--list` | 書き出さずに録音を一覧表示します。 |
| `--all` | 全録音を書き出します。 |
| `--search TEXT` | Unicode正規化を行い、大文字小文字を区別しない部分一致でタイトルを絞り込みます。 |
| `--from DATE` | `DATE` 以降（指定日時を含む）の録音に絞り込みます。 |
| `--to DATE` | `DATE` 以前（指定日時を含む）の録音に絞り込みます。時刻を省略するとその日全体を含みます。 |
| `--output DIR`, `-o DIR` | 書き出し先ディレクトリです。 |
| `--dry-run` | ソースと出力先を解決して結果を表示しますが、書き出しファイル、ログ、出力ディレクトリを作りません。 |
| `--json` | `--list` の結果を1つのJSON配列として出力します。 |
| `--include-trash` | 「最近削除した項目」の録音を含めます。テキスト一覧には `STATUS` 列を追加します。 |
| `--db PATH` | ボイスメモデータベースのパスを上書きします。 |
| `--no-set-times` | 書き出したファイルの `mtime` と `atime` を設定しません。 |
| `--version` | ツールのバージョンを表示して終了します。 |

`--from`/`--to`、`--all`/`--search`/`--list`、`--include-trash`、`--dry-run`、`--json` は自由に組み合わせられます。タイトルと日付の条件はANDで適用されます。

## 日付フィルタ

`--from` と `--to` で使える形式:

- `YYYY-MM-DD`
- `YYYY-MM-DD HH:MM`
- `YYYY-MM-DD HH:MM:SS`

両端は指定日時を含み、片側だけの指定もできます。時刻を省略した `--to` はその日全体を含みます（内部的にはその日の `23:59:59.999999` として扱われます）。入力日時はローカル時刻として解釈し、CLIが各録音から算出して `--list` に表示する `DATE` 列と同じ基準で比較します。

例 — 2026年7月の録音だけを書き出す:

```bash
python3 export_voice_memos.py \
  --all \
  --from 2026-07-01 \
  --to 2026-07-31 \
  --output ~/Desktop/voice-memos-export
```

ローカルの `DATE` 値がデータベースからどう算出されるかは [design-ja.md](design-ja.md) を参照してください。

## 「最近削除した項目」

既定では、「最近削除した項目」の録音を一覧、検索、dry-run、書き出しから除外します。含める場合は `--include-trash` を指定してください。テキスト一覧には `STATUS` 列が追加され、JSONオブジェクトには常に追加フィールド `status`（`active` または `trash`）が含まれます。

判定に使うデータベースのフィールドについては [design-ja.md](design-ja.md) を参照してください。

## 一覧出力

テキスト出力は次の形式です（以下のタイトルは架空です）。

```text
Total recordings: 3 (matched: 2)
KEY                DATE             DURATION LOCAL   TITLE
pk:101             2026-08-27 10:00     0:42 yes     Project kickoff
pk:102             2026-08-26 15:30  1:02:03 icloud  Project interview
```

`LOCAL` は3つの状態を区別します。

| 値 | 意味 |
|---|---|
| `yes` | 音声ファイルをローカルで利用できます。 |
| `icloud` | iCloudプレースホルダはありますが、録音はローカルに未ダウンロードです。書き出し時はスキップします。 |
| `missing` | データベース行はありますが、ローカルファイルもiCloudプレースホルダも見つかりません。書き出し時は失敗として扱い、残りを続行します。 |

`--json` を指定すると、stdoutにはJSON配列だけを出力します。0件一致の `--list --json --search TEXT` は `[]` を返し、終了コードは0です。

## 書き出し結果と診断情報

書き出しは録音ごとに1行を出力し、その後にTotal、Exported、Skipped、Failed件数を表示します。`--dry-run` は結果行に `[dry-run]` を付け、成功見込みを `would export` と表示し、音声、診断ログ、出力ディレクトリなど何も作成しません。

実際の書き出しでは、1件以上のスキップまたは失敗がある場合だけ、出力先ディレクトリへの診断ログ作成を試みます。作成に成功するとパスを表示します。ログはJSON Lines形式で、スキップ・失敗した録音ごとに、録音識別子、タイトル、ソースパス、出力先パス、結果、例外の型、例外メッセージを記録します。私的なタイトルやパスを含み得ますが、音声そのものは含まず、外部へ送信しません。

## 終了コード

| コード | 意味 |
|---|---|
| `0` | 成功。検索一致が0件の `--list`、またはスキップも失敗もない書き出しを含みます。 |
| `1` | 致命的エラー。引数不正、データベース/出力先エラー、書き出し時の検索一致0件、または中断です。 |
| `2` | 書き出しを完了したものの、1件以上のスキップまたは失敗がありました。 |
